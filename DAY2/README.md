## 1. Concepts Learned

### 1.1 Messages and Roles

LLM conversations consist of messages with different roles.

- **System:** Provides instructions and defines the model's behaviour.
- **User:** Contains the input or question from the customer.
- **Assistant:** Contains the response generated by the LLM.

These roles help the model understand the context and purpose of each message.
 
### 1.2 System Prompt

A system prompt defines how an AI assistant should behave.

I learned to structure system prompts using four important sections:

- **ROLE:** Defines the identity of the assistant.
- **FACTS:** Provides business-specific information.
- **RULES:** Defines restrictions and expected behaviour.
- **FORMAT:** Specifies the response style and length.

I applied this structure to create business-specific assistants for Sweet Crumbs Home Bakery and PrintSmart Printing Shop.

### 1.3 Few-Shot Prompting

Few-shot prompting involves providing a few input-output examples to an LLM so that it understands the expected response pattern.

It helps improve consistency in response formatting and task execution.

### 1.4 JSON Output

JSON (JavaScript Object Notation) is a structured format used to represent information as key-value pairs.

I experimented with instructing the LLM to extract customer order details in JSON format.

Example:

```json
{
    "name": "Varun",
    "item": "chocolate cake",
    "qty": 2,
    "date": "2026-11-28",
    "eggless": true
}
```

I then used Python's `json.loads()` to convert the JSON response into a Python dictionary.

```python
import json

try:
    order = json.loads(reply)
    print("Valid JSON!")
    print(order)

except json.JSONDecodeError:
    print("Invalid JSON returned by the bot!")
```

This makes it easier to process customer information programmatically instead of manually extracting details from natural-language responses.

### 1.5 Conversation Memory

An LLM API does not automatically retain previous conversations between independent requests.

I learned to implement basic conversation memory manually using Python lists.

The process involves:

1. Storing user messages.
2. Storing assistant responses.
3. Sending previous messages along with the new question.
4. Removing older messages to control the conversation history.

I experimented with:

```python

```

By limiting the conversation history, I observed how the assistant could lose information introduced in earlier turns.

### 1.8 Python Decorators

A decorator allows us to extend or modify a function's behaviour without changing its original implementation.

I explored the relationship:

```python
@decorator
def function():
    pass
```

This is equivalent to:

```python
function = decorator(function)
```

I implemented a logging decorator using Python's `functools.wraps`.

```python
import functools

def log_call(func):

    @functools.wraps(func)
    def wrapper(*args, **kwargs):

        result = func(*args, **kwargs)

        print(
            f"[LOG] {func.__name__}{args} -> {result!r}"
        )

        return result

    return wrapper
```

I applied it to the printing price calculation function to log function calls and their returned results.

### Step 3: Implementing the Printing Price Calculator

Created a reusable Python function to calculate printing charges.

```python
def get_printing_price(
    pages: int,
    print_type: str,
    sides: str
) -> int:

    if pages <= 0:
        raise ValueError("Pages must be greater than zero.")

    print_type = print_type.lower().strip()
    sides = sides.lower().strip()

    if print_type == "black and white":

        if sides == "single":
            price = 1

        elif sides == "double":
            price = 2

        else:
            raise ValueError("Invalid printing sides.")

    elif print_type == "color":
        price = 10

    else:
        raise ValueError("Invalid printing type.")

    return pages * price
```

This function calculates the printing cost based on the number of pages, printing type, and printing sides.

### Step 4: Applying a Decorator

### Step 5: Implementing Conversation History

Maintained conversation history using a Python list.

The application stores previous user and assistant messages and sends a limited portion of the conversation to the LLM with every new request.

```python
MAX_TURNS = 8

history = [
    {"role": "system", "content": SYSTEM}
]

recent = [history[0]] + history[1:][-MAX_TURNS:]
```

This helps control how much previous conversation information is included in each API request.

### Step 6: Handling API Errors

Implemented exception handling for API-related failures.

```python
try:
    response = client.chat.completions.create(
        model=MODEL,
        messages=recent,
        temperature=0.3
    )

    reply = response.choices[0].message.content

except RateLimitError:
    reply = "We're a little busy. Please try again in a minute."

except APIConnectionError:
    reply = "Unable to connect right now. Please try again shortly."
```

This allows the assistant to provide meaningful responses when API requests fail.
